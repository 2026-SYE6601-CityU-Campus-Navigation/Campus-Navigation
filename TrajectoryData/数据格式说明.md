# 轨迹数据文件夹（TrajectoryData）说明

接收三端（HarmonyOS / iOS / Android）App 上传的室内外轨迹数据，供三维建模、路径规划与 AI 路引生成使用。

## 目录结构

```
D:\CityUproject\TrajectoryData\
├── 轨迹数据.jsonl          统一接收文件（汇总三端数据；由后端/harness 聚合写入）
├── Harmony\轨迹数据.jsonl  HarmonyOS 端轨迹（RoomMarkerHarmony 写入）
├── iOS\轨迹数据.jsonl      iOS 端轨迹
├── Android\轨迹数据.jsonl  Android 端轨迹（CampusNavDemo 写入）
└── 数据格式说明.md          本文件
```

## 文件格式：JSON Lines（.jsonl）

- 每行一条完整的 JSON 对象，代表**一个轨迹点**
- **追加写**：App 只往文件末尾追加新行，绝不整文件重写（防止数据损坏、并发安全）
- 编码 UTF-8（无 BOM）；文件中不允许写注释，说明都在本 md 里
- 三端各自写自己的子文件夹，互不干扰；`轨迹数据.jsonl` 顶层文件由后端定时合并三端数据

## 字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| platform | string | 是 | `Harmony` / `iOS` / `Android` |
| sessionId | string | 是 | 一次导航会话的唯一 ID（UUID） |
| recordedAt | string | 是 | ISO 8601 时间戳，含时区，如 `2026-09-25T10:30:12+08:00` |
| lat / lng | number | 室外必填 | WGS84 经纬度 |
| floor | number | 室内建议 | 楼层（整数；地下为负），城大立体校园的关键字段 |
| altitude | number | 否 | 高度（米），来自气压计/GNSS |
| pressure | number | 否 | 气压计读数（hPa），辅助推算楼层 |
| heading | number | 否 | 航向角（度，0~360） |
| step | number | 否 | 计步器累计步数 |
| mode | string | 否 | `outdoor` / `indoor` |
| anchor | string | 否 | 最近的关键节点/锚点名称，如 `AC1-电梯口`（锚点校正用） |
| extra | object | 否 | 其他传感器读数（地磁三分量、加速度等） |

## 示例行（一行一条）

```json
{"platform":"Android","sessionId":"3f2a9c1e-6b4d-4f8a-9c0e-1d2b3a4c5d6e","recordedAt":"2026-09-25T10:30:12+08:00","lat":22.33780,"lng":114.17250,"floor":3,"altitude":42.5,"pressure":1012.3,"heading":87.2,"step":120,"mode":"indoor","anchor":"AC1-电梯口","extra":{"magX":-12.4,"magY":3.1,"magZ":41.0}}
```

## 写入规则（三端统一）

1. 每次定位采样（如 1Hz）追加一行；进入/离开室内、切换楼层时务必写一行含 `mode` 与 `floor` 的记录
2. `sessionId` 在 App 启动一次导航时生成，导航结束保持不变
3. 文件不存在则创建后写入；写之前先确保文件夹存在
4. 建议每行结尾换行符为 `\n`（Linux 风格），Windows 端读写作兼容处理
